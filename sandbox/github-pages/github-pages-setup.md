# Инструкция по настройке базы знаний на GitHub Pages (на базе Zensical)

Актуальное руководство по развертыванию современной, высокопроизводительной базы знаний с использованием нового движка **Zensical** (на базе Rust) и автоматической публикации через GitHub Actions напрямую из исходного кода.

## Шаг 1. Подготовка репозитория на GitHub
1. Создайте **публичный (Public)** или **приватный (Private)** репозиторий на GitHub.
2. Разрешите запуск **GitHub Actions** в настройках репозитория.
3. Настройте права воркфлоу для возможности публикации сайта:
   * Перейдите в **Settings** -> **Actions** -> **General**.
   * В самом низу страницы в разделе **Workflow permissions** переключите маркер на **Read and write permissions** и нажмите **Save**.

---

## Шаг 2. Создание структуры папок и файлов
Вся документация, скрипты и медиафайлы должны находиться строго внутри каталога `docs`. Создайте в репозитории следующую структуру:

* `zensical.toml` — главный конфигурационный файл сайта в современном формате TOML (создается в корне).
* `docs/` — папка в корне репозитория для всех материалов базы знаний.
* `docs/index.md` — главная страница сайта с плиточной сеткой карточек (создается внутри `docs`).
* `docs/glossary.md` — файл алфавитного глоссария и терминов (создается внутри `docs`).
* `docs/assets/` — выделенная папка для медиафайлов (картинок, схем и скриншотов).
* `docs/code/` — папка для хранения чистых файлов исходного кода, конфигураций и SQL-скриптов.
* `.github/workflows/` — техническая папка для сценариев автоматизации.
* `.github/workflows/ci.yml` — современный сценарий деплоя сайта напрямую в инфраструктуру GitHub Pages.

---

## Подробное описание назначения файлов и папок

### В корневом каталоге (технические файлы)
* **`zensical.toml`** — единый пульт управления вашей базой знаний. Этот файл нативно настраивает встроенную тему Material, шрифты, адаптивные темы оформления, навигацию «хлебные крошки» и отключает критические падения сборки из-за кириллических ссылок глоссария, подстраивая проект под требования ИИ (RAG-систем).
* **`.github/workflows/ci.yml`** — сценарий автоматизации для робота GitHub Actions. Каждый раз при сохранении изменений робот устанавливает компилятор Zensical, собирает файлы разметки в готовый HTML-сайт, упаковывает его в защищенный артефакт и публикует напрямую на сервера GitHub Pages без создания лишних скрытых веток в репозитории.

### Внутри папки `docs/` (контент вашей базы знаний)
* **`docs/index.md`** — главная страница вашего сайта. Благодаря встроенным возможностям Zensical, текстовые списки здесь оформляются в виде плиточных адаптивных карточек с иконками, превращая страницу в удобный хаб-витрину.
* **`docs/glossary.md`** — файл терминов. Текст в нем остается абсолютно «стерильным» от латинского синтаксического шума, что идеально подходит для RAG-систем, а веб-движок автоматически строит по нему правое меню навигации.

### Внутренние ресурсы (`assets/` и `code/`)
* **`docs/assets/`** — каталог для скриншотов и иллюстраций. Хранение внутри `docs/` гарантирует их компиляцию, а применение Markdown-классов вроде `{ .card .shadow }` автоматически добавляет картинкам эстетичные тени и скругления.
* **`docs/code/`** — папка для хранения скриптов (например, `init-db.sql`). Позволяет авторам автоматически втягивать код в статьи без копипаста с помощью конструкций вида ` --8<-- "docs/code/filename"`, а пользователям — скачивать чистые файлы по прямым ссылкам.

## Шаг 3. Настройка источника публикации (GitHub Pages)
В отличие от старых движков, Zensical использует современный метод публикации без промежуточных Git-веток:

1. Перейдите во вкладку **Settings** (Настройки) вашего репозитория на GitHub.
2. В левом вертикальном меню выберите раздел **Pages**.
3. В блоке **Build and deployment** найдите выпадающий список **Source** (Источник).
4. Вместо *Deploy from a branch* строго выберите режим **`GitHub Actions`**.

---

## Шаг 4. Обновление материалов и проверка сайта
1. Все изменения, добавления статей и медиафайлов производятся авторами внутри папки `docs/`.
2. После отправки изменений (Git Push) перейдите во вкладку **Actions** в верхней панели GitHub для контроля сборки.
3. Сборка Zensical на базе Rust отработает мгновенно (в среднем за 20–30 секунд) и окрасится в **зелёную галочку**. Финальный деплой выполнится как вложенный шаг прямо внутри этого процесса.
4. Ссылка на готовый сайт отобразится прямо на вкладке настроек **Settings -> Pages**. При первом открытии обязательно используйте комбинацию клавиш **`Ctrl + F5`** для принудительного сброса кэша стилей в браузере.
