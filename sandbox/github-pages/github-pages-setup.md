# Инструкция по настройке базы знаний на GitHub Pages

Актуальное руководство по развертыванию современной базы знаний с использованием движка **MkDocs Material** и автоматического развертывания через GitHub Actions.

## Шаг 1. Подготовка репозитория на GitHub
1. Создайте **публичный (Public)** репозиторий на GitHub.
2. Убедитесь, что в настройках репозитория разрешен запуск **GitHub Actions**.

## Шаг 2. Создание структуры папок и файлов
Вся документация и медиафайлы должны находиться строго внутри каталога `docs`. Создайте в репозитории следующую структуру:

* `mkdocs.yml` — главный конфигурационный файл сайта (создается в корне).
* `docs/` — папка в корне репозитория для всех материалов базы знаний.
* `docs/index.md` — главная страница сайта (создается внутри `docs`).
* `docs/glossary-revised.md` — файлы статей и документов (создаются внутри `docs`).
* `docs/github-pages-setup.md` — этот текущий файл с инструкцией (создается внутри `docs`).
* `docs/images/` — папка для хранения всех иллюстраций и схем.
* `.github/workflows/` — техническая папка для сценариев автоматизации.
* `.github/workflows/deploy.yml` — сценарий сборщика для компиляции сайта.

---

## Подробное описание назначения файлов и папок

### В корневом каталоге (технические файлы)
* **`mkdocs.yml`** — главный пульт управления вашей базой знаний. Этот файл сообщает движку, какое оформление использовать (тему Material), на каком языке отображать интерфейс (русский) и какие функции активировать (встроенный поиск, автоматическое правое меню статьи, дневной/ночной режимы и кнопку копирования кода).
* **`.github/workflows/deploy.yml`** — сценарий автоматизации (скрипт для робота GitHub Actions). Каждый раз, когда вы сохраняете изменения в статьях, этот робот просыпается, скачивает нужную версию Python, устанавливает движок MkDocs Material, компилирует файлы разметки в красивый готовый HTML-сайт и публикует его в скрытую ветку `gh-pages`.

### Внутри папки `docs/` (контент вашей базы знаний)
* **`docs/index.md`** — главная (стартовая) страница вашего сайта. Это первое, что видит пользователь, когда переходит по ссылке. Обычно здесь размещают приветствие, описание проекта и верхнеуровневый список ссылок на ключевые разделы базы знаний.
* **`docs/glossary-revised.md`** — пример полноценной статьи вашей базы знаний. Благодаря структуре MkDocs, этот файл автоматически получит интерактивное правое меню со скроллингом, построенное строго по вашим внутренним заголовкам `##` и `###`.
* **`docs/github-pages-setup.md`** — этот текущий файл с инструкцией. Он автоматически отобразится в левом меню сайта как самостоятельный справочный раздел для администраторов базы знаний.

### Внутренние медиаресурсы
* **`docs/images/`** — папка, где хранятся все ваши схемы, скриншоты, логотипы и иллюстрации. Хранение этой папки строго внутри `docs/` гарантирует, что движок сайта успешно скопирует картинки при сборке, и ссылки на изображения внутри статей (`![текст](images/картинка.png)`) никогда не сломаются.

## Шаг 3. Настройка источника публикации (GitHub Pages)
1. Перейдите во вкладку **Settings** (Настройки) вашего репозитория на GitHub.
2. В левом вертикальном меню выберите раздел **Pages**.
3. В блоке **Build and deployment** найдите раздел **Branch** (Ветка).
4. Вместо ветки *main* выберите ветку **`gh-pages`** (она автоматически создается роботом после первого сохранения файлов).
5. В соседнем выпадающем списке папок оставьте каталог **`/root`**.
6. Нажмите кнопку **Save** (Сохранить).

## Шаг 4. Обновление материалов и проверка сайта
1. Все изменения, добавления статей и новых папок производятся внутри папки `docs/`.
2. После сохранения изменений перейдите во вкладку **Actions** в верхней панели GitHub для контроля сборки.
3. Дождитесь, пока индикатор сборки сменится на **зелёную галочку**.
4. Перейдите по адресу вашего сайта. При первом открытии или обновлении структуры обязательно используйте комбинацию клавиш **`Ctrl + F5`** для принудительного сброса кэша стилей в браузере.
