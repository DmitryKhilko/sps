## Требования к стеку технологий базы знаний

Перед созданием базы знаний были определены требования, которым должен удовлетворять выбираемый технологический стек:

- Бесплатность инструментов для ведения базы знаний. 
- Доступность базы знаний и инструментов для её ведения в любой точке мира.
- Возможность групповой работы с базой знаний. 
- Версионирование статей базы знаний.
- Возможность сохранять копии базы знаний на персональный компьютер.
- Простота и скорость создания, изменения, публикации статей базы знаний.
- Возможность быстрого переноса базы знаний в иной репозиторий.
- Возможность загрузки базы знаний и её использования в RAG-системах.

[*Переход вверх*][3]

## Выбранные инструменты для ведения базы знаний

На основании требований, приведенных в разделе [Требования к стеку технологий базы знаний][5], были выбраны  следующие 
инструменты для ведения базы знаний:
- репозиторий GitHub;
- интегрированная среда разработки и редактирования VS Code;
- формат разметки текстовых данных Markdown.

[*Переход вверх*][3]

### GitHub

Репозиторий GitHub обеспечивает:

- **Централизованное облачное хранение данных**: Финальные и промежуточные версии файлов статей базы знаний хранятся в 
едином хранилище, позволяющем вести синхронизацию файлов между различными рабочими компьютерами.
- **Ведение непрерывного аудита изменений**: Ведение непрерывного аудита изменений посредством фиксации коммитов 
позволяет восстанавливать предыдущие версии документов и идентифицировать авторов правок.
- **Инфраструктуру для совместной работы**: Репозиторий предоставляет инфраструктуру для совместной работы (механизмы 
Pull Requests и Issues) и разграничения прав доступа пользователей.
- **Возможность быстрого переноса базы знаний в иной репозиторий**: База знаний представляет собой набор файлов и 
каталогов, который можно быстро перенести в иной репозиторий. 

[*Переход вверх*][3]

### VS Code

Интегрированная среда разработки и редактирования VS Code обеспечивает:

- Локальный интерфейс для создания, модификации, сквозного поиска текстовых файлов.
- Управление Git-репозиторием.

[*Переход вверх*][3]

### Markdown

Базу знаний планируется "обернуть" RAG-системой. Markdown - безальтернативный лидер для [RAG][8]. Запланировано 
использовать Markdown как целевой формат. Все остальные документы (PDF, DOCX, HTML) должны конвертироваться в Markdown 
перед загрузкой в векторную базу.

Почему Markdown лучший выбор:

- **Идеальная структура для чанкинга**: Заголовки (#, ##), списки и блоки кода в Markdown служат естественными границами 
для разбиения текста. Это позволяет алгоритмам делить документ на смысловые блоки, не разрывая контекст.
- **Токен-эффективность**: Markdown требует значительно меньше токенов для хранения той же информации по сравнению с 
HTML (экономия до 25%), так как не содержит тегов, стилей и скриптов. Это снижает стоимость эмбеддинга и генерации.
- **Чистота контента**: В отличие от PDF, в Markdown нет проблем с «двойными колонками», «плавающими» картинками или 
артефактами сканирования. Текст идет в правильном порядке чтения.
- **Легкость редактирования**: Базу знаний можно править в любом текстовом редакторе, использовать Git для 
версионирования и легко автоматизировать процессы (CI/CD для документации).
- **Долгосрочная сохранность и переносимость данных**: Markdown обеспечивает долгосрочную сохранность и переносимость 
данных, поскольку файлы представляют собой плоский текст (.md), независимый от программной среды.
- **Оптимизация процессов контроля версий**: Оптимизирует процессы контроля версий благодаря строчной структуре файлов, 
минимизирующей объем хранилища и упрощающей дифференциацию (diff) изменений.
